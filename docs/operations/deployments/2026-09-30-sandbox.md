## Compatibility and recovery

No-proc mode deliberately does not expose the parent container's procfs.
Node `process.memoryUsage()`/`rss()` and other proc-dependent interfaces can fail
with `ENOENT`; ordinary npm/Python command checks above do not certify every
possible toolchain. npm uses a private scratch home, and scratch-file creation
does not imply a host-file write. The canary verifies the host sentinel remains
unreadable and unchanged, and reports scratch shadow writes separately.

The previous image is retained as `ai-ide:rollback-20260930-before-sandbox`.
The operator-only backup directory
`/root/crownforge-deployments/20260930-approval-sandbox` contains the original
container/Compose identity, workspace/config backups, test scripts and diagnostic
results. Restore application and runtime settings if rollback is needed; do not
overwrite newer user data as part of an image rollback. The old runtime itself
had the known sandbox failure, so rolling back restores prior availability, not
working Agent shell isolation.
